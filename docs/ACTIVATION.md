# Recommended minimal path (no spend, no new accounts, no hosting)
Use the publishing flows that already exist as the publishers, and use this repo only for what they lack: verified source packets, a pre-review draft check, a hash of the exact approved text, and a metrics ledger.
1. Source packets (no model, no key): `python -m socialteam leads` reads the official feeds, runs the deterministic verification gate, and prints JSON source packets. Run live on 2026-11-25 against public feeds only: 2 verified packets returned (read-only, no private service).
2. Writing: the existing recurring task for each platform writes the text from the packet (this replaces the Grok/free-model writer; a disclosed substitution).
3. Pre-review check: `python -m socialteam check-draft ITEM_ID TEXT_FILE` fails on numbers not in the source, missing source URL, first-person wording and hedged KEV meaning, and prints the content hash of that exact text. No model.
4. Review and approval: the user approves the exact text in WhatsApp as today (his words and message id are the approval). The localhost review page is a developer tool and is not needed on this path.
5. Publishing and scheduling: the existing flows publish with their own logged-in sessions, as LinkedIn, Medium and TikTok already do. Nothing new is built or needed.
6. Analytics: those tasks read the platforms' own analytics pages read-only and produce CSV rows (post_id or URL, platform, date, impressions, engagements); `python -m socialteam metrics FILE` ingests them and reports. Needs the user's existing read access only.
Runs persistently: the existing recurring Instinct tasks and their wakes. Does not run persistently: this build environment (temporary files, no server), the localhost review page, and the SQLite files unless a task re-creates them each run. State that must survive (posted ledger, metrics) has to live in the task's own records or the user's Drive.
Not on this path because each needs an always-on server or paid access: Postiz (2 GB VM with Postgres, Redis, Temporal; no free cloud plan, $29/month; self-host needs your own LinkedIn/X developer apps), TryPost self-host (PHP 8.4, Node, Postgres/MySQL, Redis, 1 GB), X API posting ($0.015 per post, $0.20 with a link, prepaid), n8n, Metabase, Langfuse. The draft/schedule adapters remain as tested code; guarded schedule or publish code for them should be written only when one of those servers exists, with one post per call, approved hash plus approval evidence required, dry run by default.
Smallest user-owned decision: yes or no to "use my existing LinkedIn/X/Medium/TikTok flows as the publishers, writing with the assistant instead of Grok, approving each exact text in WhatsApp as now, nothing self-hosted and nothing paid".

# Full list of other activation items (not minimal)
Nothing below has been done. Each item needs an owner decision. Offline code for items 2 to 5 exists and is tested only against fakes.
1. Model route for a clean live run. Needs: a decision on which route to use and how many calls (free routes were throttled 2026-11-25; Grok needs paid credits). Unlocks: a real strategist/writer/designer/scheduler run under the new quality checks, which is the only thing that shows output quality. Until then no real draft exists.
2. Publishing target (Postiz or TryPost). Needs: an instance the owner runs or pays for, a workspace API key, connected LinkedIn/X accounts, and their ids. Unlocks: `publish-drafts` creates DRAFTS in that tool; a human promotes them there. Both vendors' docs say API keys can publish directly, which is why this code sends drafts only. TikTok needs a video file; Medium is Postiz only.
3. n8n. (Ran once for real on a temporary AWS instance on 2026-11-25: webhook received the approved export; see INTEGRATION_EVIDENCE.md. Not a standing service.) Needs: an n8n instance (Node >= 22) (self-hosted is free under its license terms for internal use; the owner should confirm their use fits) and a webhook with header auth (preferred: the native Webhook Header-auth credential, see docs/n8n/handoff-workflow.headerauth.UNTESTED.json and deploy/README.md; run `python -m socialteam preflight` first). Unlocks: approved posts trigger the owner's own workflows (notify, forward, schedule). The workflow itself still has to be built.
4. Langfuse. Needs: Langfuse Cloud or self-hosted project keys and an OK to send run metadata (no content) to it. Unlocks: traces per item.
5. Metabase. (Attached analytics.db and ran SQL once on AWS, test data only.) Needs: a self-hosted Metabase (Java 21) (SQLite connector is not on Cloud) pointed at analytics.db, and real post metrics exported to CSV from each platform. Unlocks: dashboards. Without real metrics only the pipeline funnel exists.
6. Existing flows (TikTok/LinkedIn/Medium/X workers the owner already runs): not inspected or integrated. Needs: which flow, and permission to read its interface. The approved export and the n8n payload are the intended hand-off.
7. Crawl4AI, Repomix, ComfyUI, Remotion: only if the owner wants JS crawling, code-aware prompts, generated images or video. Each has costs or license conditions listed in COVERAGE.md.
