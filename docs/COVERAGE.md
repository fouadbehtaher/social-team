# Coverage against the original idea (checked 2026-11-25)
The idea: six roles (trends, strategy, writing, design, scheduling and publishing, analysis) run by one manager graph, built from 12 open-source projects.
Status words: LIVE = ran against a real model or service. OFFLINE = tested only with fakes or mocks. NONE = not built.
Licenses come from the GitHub API and LICENSE files read on 2026-11-25. This is not a legal review and not a security audit.

| # | Project | License | What the idea wanted | Status here |
|---|---|---|---|---|
| 1 | LangGraph (langchain-ai/langgraph) | MIT | Manager that runs the roles | Used as the graph runtime. LIVE: the graph ran scout, trend_scout, strategist and writer on one real item. |
| 2 | n8n | Sustainable Use License (not OSI) | Automation, approvals, scheduling | OFFLINE. `n8n-handoff` POSTs the hash-verified approved export to an n8n Webhook node with header auth (contract: docs.n8n.io Webhook node; 16MB default body limit enforced). `publish: false` is in the payload, it is a notification, not a publish command. Dry run by default, https/localhost only, refuses an empty or tampered export. No n8n instance exists, nothing sent. The n8n workflow itself is not written.  AWS TRIAL 2026-11-25: a real n8n 2.35.7 received the hash-verified approved export (HTTP 200, execution success); wrong or missing header got 500 (not 401, see INTEGRATION_EVIDENCE). Not a standing service; torn down. |

Crawl4AI would add JavaScript rendering and broad crawling, which widens what untrusted text reaches the model. Not built; needs an owner decision on which extra sites are in scope. |

The old `/api/public/ingestion` endpoint is deprecated (Cloud sunset 2026-11-16), so it is not used. Dry run by default. Payload shape is tested locally only; never accepted by a real Langfuse. |

Review and approval path: `seed-test-item` creates one clearly labeled TEST FIXTURE (fixed text, no model, no real source) and `review-serve` shows it on http://127.0.0.1 with token-protected approve/reject (proof screenshot: review-test-path.png). That proves the review code path, not model acceptance. Unlike the earlier static page, approval can now happen in the browser, still only by the human typing the approval token.
Roles in code: trend_scout, strategist, writer, designer, scheduler (a proposal only, it cannot schedule), analyst (metrics CSV), plus a human approval gate bound to a content hash.
The roles are six separate prompts on one model, not six autonomous agents.
LIVE results so far (free routes, one item, 2026-11-25): trend_scout (3 items), strategist, writer. NOT live: designer, scheduler, card render from a real designer result, review queue with a real item, approval, analytics, any publishing.
The first captured Medium draft failed the new quality checks (first person, hedged KEV meaning) and was reset by `recheck`; the next real draft has not been generated.
